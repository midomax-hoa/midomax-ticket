## 2. Điểm quan trọng trước khi làm

- **Ứng dụng helpdesk chỉ chạy được trên MySQL**: driver `com.mysql.cj.jdbc.Driver`, dialect `org.hibernate.dialect.MySQLDialect`, và Flyway dùng gói `flyway-mysql` (xem `source/helpdesk/src/main/resources/application.properties` và `pom.xml`).
  → Đẩy sang PostgreSQL là để **nơi khác dùng dữ liệu** (báo cáo, phân tích, hệ thống khác), **không phải** để chạy ứng dụng helpdesk trên PostgreSQL. Muốn chạy app trên PostgreSQL là một việc khác hẳn, phải đổi driver, dialect, và viết lại toàn bộ migration V1–V10.
- **Không có khóa ngoại trong bản MySQL gốc** — `parent_id` và `work_report_id` chỉ là cột bigint thường. Bản PostgreSQL bên dưới giữ nguyên như vậy để dữ liệu vào được theo thứ tự bất kỳ; phần thêm khóa ngoại là tùy chọn ở mục 6.
- **Múi giờ**: MySQL lưu `datetime` không kèm múi giờ. Bên PostgreSQL phải dùng `timestamp without time zone` — nếu dùng `timestamptz` thì giờ sẽ bị dịch theo múi giờ server.

## 3. DDL cho PostgreSQL (chạy trước khi nạp dữ liệu)

```sql
CREATE TABLE work_reports (
  id                  bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  project_name        varchar(255) NOT NULL,
  task_title          varchar(255) NOT NULL,
  assignee            varchar(255) NOT NULL,
  created_by          varchar(255) NOT NULL,
  watchers            varchar(255),
  status              varchar(255) NOT NULL,
  progress_percentage integer      NOT NULL,
  start_date          timestamp(6),
  due_date            timestamp(6),
  daily_report        text,
  priority            varchar(255),
  estimated_time      varchar(255),
  logged_hours        double precision,
  tags                varchar(255),
  is_timer_running    smallint,
  timer_started_at    timestamp(6),
  parent_id           bigint,
  delay_reason        text,
  completed_at        timestamp,
  owner_confirmed     smallint     NOT NULL DEFAULT 0,
  created_at          timestamp(6),
  updated_at          timestamp(6)
);
CREATE INDEX idx_work_reports_created_by ON work_reports (created_by);
CREATE INDEX idx_work_reports_parent_id  ON work_reports (parent_id);

CREATE TABLE work_subtasks (
  id             bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  work_report_id bigint       NOT NULL,
  title          varchar(255) NOT NULL,
  assignee       varchar(255),
  completed      smallint     NOT NULL,
  created_at     timestamp(6),
  updated_at     timestamp(6)
);
CREATE INDEX idx_work_subtasks_report ON work_subtasks (work_report_id);

CREATE TABLE work_comments (
  id             bigint       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  work_report_id bigint       NOT NULL,
  author         varchar(255) NOT NULL,
  content        text         NOT NULL,
  created_at     timestamp(6),
  updated_at     timestamp(6)
);
CREATE INDEX idx_work_comments_report ON work_comments (work_report_id);
```

### Vì sao dùng `smallint` cho 3 cột cờ

`is_timer_running`, `owner_confirmed`, `completed` bên MySQL là `bit(1)` / `tinyint(1)`, trong file `.sql` được ghi ra dưới dạng `0` / `1`. PostgreSQL **không tự ép** `0` / `1` sang `boolean`, nên nếu khai báo `boolean` thì câu INSERT sẽ lỗi.

Dùng `smallint` thì nạp thẳng file không phải sửa gì. Muốn đổi sang `boolean` cho đúng kiểu PostgreSQL thì **nạp dữ liệu xong rồi mới đổi**:

```sql
ALTER TABLE work_reports  ALTER COLUMN is_timer_running TYPE boolean USING is_timer_running::int::boolean;
ALTER TABLE work_reports  ALTER COLUMN owner_confirmed  TYPE boolean USING owner_confirmed::int::boolean;
ALTER TABLE work_subtasks ALTER COLUMN completed        TYPE boolean USING completed::int::boolean;
```

### Bảng ánh xạ kiểu dữ liệu

| MySQL | PostgreSQL | Ghi chú |
|---|---|---|
| `bigint AUTO_INCREMENT` | `bigint GENERATED BY DEFAULT AS IDENTITY` | `BY DEFAULT` để nạp được id chỉ định sẵn |
| `varchar(255)` | `varchar(255)` | |
| `text` | `text` | |
| `datetime(6)` | `timestamp(6)` | **không** dùng `timestamptz` |
| `datetime` | `timestamp` | cột `completed_at` |
| `int` | `integer` | |
| `double` | `double precision` | |
| `bit(1)`, `tinyint(1)` | `smallint` | xem giải thích ở trên |
| `KEY ten_index (cot)` | `CREATE INDEX ten_index ON bang (cot)` | index phải tách thành câu lệnh riêng |

## 4. Chuyển file `.sql` sang cú pháp PostgreSQL

**Tin tốt:** đã kiểm chứng file dữ liệu **không chứa ký tự escape nào** (`\'` = 0 lần, `\\` = 0 lần). Nghĩa là toàn bộ phần `INSERT ... VALUES (...)` dùng thẳng cho PostgreSQL được, **không phải sửa một chữ nào**.

Chỉ cần thay **9 dòng đầu** (từ dòng 3 tới dòng 9) là xong:

| Dòng trong file MySQL | Thay bằng (PostgreSQL) |
|---|---|
| `SET NAMES utf8mb4;` | *(bỏ — PostgreSQL không có lệnh này)* |
| `DELETE FROM work_comments;` | giữ nguyên |
| `DELETE FROM work_subtasks;` | giữ nguyên |
| `DELETE FROM work_reports;` | giữ nguyên |
| `ALTER TABLE work_reports AUTO_INCREMENT = 1;` | *(bỏ — thay bằng `setval` ở cuối, xem dưới)* |
| `ALTER TABLE work_subtasks AUTO_INCREMENT = 1;` | *(bỏ)* |
| `ALTER TABLE work_comments AUTO_INCREMENT = 1;` | *(bỏ)* |

Rồi **thêm vào cuối file** phần đồng bộ lại bộ đếm id (bắt buộc — không có bước này thì lần thêm bản ghi mới sau đó sẽ bị trùng khóa chính):

```sql
SELECT setval(pg_get_serial_sequence('work_reports',  'id'), (SELECT COALESCE(MAX(id), 1) FROM work_reports));
SELECT setval(pg_get_serial_sequence('work_subtasks', 'id'), (SELECT COALESCE(MAX(id), 1) FROM work_subtasks));
SELECT setval(pg_get_serial_sequence('work_comments', 'id'), (SELECT COALESCE(MAX(id), 1) FROM work_comments));
```

### Script chuyển đổi (Node, chạy được ngay)

```js
// convert-to-postgres.js — chạy: node convert-to-postgres.js
const fs = require('fs');
const SRC = 'plans/reports/seed-260818-1036-work-reports-zalo-mini-app-restore.sql';
const OUT = 'plans/reports/seed-260818-1036-work-reports-zalo-mini-app-restore-postgres.sql';

let s = fs.readFileSync(SRC, 'utf8');

// 1. Bỏ các lệnh riêng của MySQL
s = s.replace(/^SET NAMES utf8mb4;\n/m, '');
s = s.replace(/^ALTER TABLE \w+ AUTO_INCREMENT = 1;\n/gm, '');

// 2. Bọc trong một giao dịch + đồng bộ lại bộ đếm id ở cuối
s = 'BEGIN;\n' + s.trimEnd() + `

SELECT setval(pg_get_serial_sequence('work_reports',  'id'), (SELECT COALESCE(MAX(id), 1) FROM work_reports));
SELECT setval(pg_get_serial_sequence('work_subtasks', 'id'), (SELECT COALESCE(MAX(id), 1) FROM work_subtasks));
SELECT setval(pg_get_serial_sequence('work_comments', 'id'), (SELECT COALESCE(MAX(id), 1) FROM work_comments));

COMMIT;
`;

fs.writeFileSync(OUT, s, 'utf8');
console.log('Da ghi', OUT);
```

Script này đã được chạy thử trên chính file dữ liệu ngày 18/08/2026: kết quả 660 dòng, **không còn lệnh nào riêng của MySQL** (`SET NAMES`, `AUTO_INCREMENT`, `ENGINE=`, dấu backtick đều = 0).

## 5. Nạp vào PostgreSQL

### Cách A — dùng `psql` (nhanh nhất, nếu máy có sẵn)

```bash
psql "postgresql://<user>:<password>@<host>:<port>/<database>" \
  -v ON_ERROR_STOP=1 \
  -f ddl-postgres.sql \
  -f plans/reports/seed-260818-1036-work-reports-zalo-mini-app-restore-postgres.sql
```

### Cách B — dùng Node + gói `pg` (máy hiện tại **không có** `psql` CLI, nên thường phải đi đường này)

```js
// push-postgres.js — chạy: npm install pg && node push-postgres.js
const fs = require('fs');
const { Client } = require('pg');

(async () => {
  const c = new Client({
    host: '<host>', port: 5432,
    user: '<user>', password: '<password>',
    database: '<database>',
    // ssl: { rejectUnauthorized: false },   // mở nếu server bắt buộc SSL
  });
  await c.connect();
  for (const f of ['ddl-postgres.sql', 'plans/reports/seed-260818-1036-work-reports-zalo-mini-app-restore-postgres.sql']) {
    await c.query(fs.readFileSync(f, 'utf8'));
    console.log('Da chay', f);
  }
  await c.end();
})().catch(e => { console.error('ERR', e.message); process.exit(1); });
```

> Nếu password chứa ký tự đặc biệt (`@`, `#`, `:`) thì **truyền theo từng field như trên**, đừng ghép thành chuỗi URL rồi parse — đã dính lỗi này với DB MySQL.

## 6. Kiểm tra sau khi nạp

```sql
-- Đếm số dòng: phải ra 62 / 323 / 52
SELECT 'reports' t, COUNT(*) n FROM work_reports
UNION ALL SELECT 'subtasks', COUNT(*) FROM work_subtasks
UNION ALL SELECT 'comments', COUNT(*) FROM work_comments;

-- 10 giai đoạn cha, đọc từ mới nhất về cũ nhất (đúng thứ tự app helpdesk hiển thị)
SELECT id, status, progress_percentage, start_date::date, due_date::date, completed_at::date, task_title
FROM work_reports WHERE parent_id IS NULL ORDER BY updated_at DESC;

-- Không được có dòng nào trễ hẹn (so với hạn của việc cha) -> phải trả về 0 dòng
SELECT c.id, c.completed_at, p.due_date
FROM work_reports c JOIN work_reports p ON p.id = c.parent_id
WHERE c.completed_at IS NOT NULL AND c.completed_at > p.due_date;

-- Ngày việc cha phải khớp min/max của việc con -> phải trả về 0 dòng
SELECT p.id
FROM work_reports p JOIN work_reports c ON c.parent_id = p.id
GROUP BY p.id, p.start_date, p.due_date
HAVING p.start_date <> MIN(c.start_date) OR p.due_date <> MAX(c.due_date);

-- Không mốc thời gian nào rơi vào thứ bảy / chủ nhật -> phải trả về 0 dòng
SELECT id FROM work_reports WHERE EXTRACT(DOW FROM start_date) IN (0, 6)
   OR EXTRACT(DOW FROM due_date) IN (0, 6)
   OR (completed_at IS NOT NULL AND EXTRACT(DOW FROM completed_at) IN (0, 6));

-- Bình luận chỉ được của dev03 -> phải chỉ ra đúng 1 dòng: dev03 | 52
SELECT author, COUNT(*) FROM work_comments GROUP BY author;

-- Không có việc con nào mồ côi -> phải trả về 0 dòng
SELECT id FROM work_reports WHERE parent_id IS NOT NULL
  AND parent_id NOT IN (SELECT id FROM work_reports);
```

### Tùy chọn: thêm khóa ngoại sau khi nạp xong

```sql
ALTER TABLE work_reports  ADD CONSTRAINT fk_work_reports_parent
  FOREIGN KEY (parent_id) REFERENCES work_reports (id) ON DELETE CASCADE;
ALTER TABLE work_subtasks ADD CONSTRAINT fk_work_subtasks_report
  FOREIGN KEY (work_report_id) REFERENCES work_reports (id) ON DELETE CASCADE;
ALTER TABLE work_comments ADD CONSTRAINT fk_work_comments_report
  FOREIGN KEY (work_report_id) REFERENCES work_reports (id) ON DELETE CASCADE;
```

## 8. Việc cần xác nhận trước khi chạy

1. **Chuỗi kết nối PostgreSQL** (host, port, database, user, password, có bắt buộc SSL không) — chưa có thông tin này thì không chạy được.
2. **Database đích là DB test hay DB thật?** File dữ liệu mở đầu bằng `DELETE FROM` cả 3 bảng — chạy nhầm trên DB thật sẽ xoá sạch dữ liệu đang có. Cần xác nhận rõ trước khi chạy.
3. **Đã có sẵn 3 bảng đó bên PostgreSQL chưa?** Nếu có rồi thì bỏ phần DDL ở mục 3 và kiểm tra kiểu dữ liệu 3 cột cờ (`smallint` hay `boolean`) để biết có phải chuyển giá trị `0`/`1` không.
4. **Có cần thêm bảng `app_users` không?** Các cột `assignee` / `created_by` / `watchers` / `author` lưu handle dạng chữ (`dev03`, `dev01`...), không phải id. Nếu hệ thống bên PostgreSQL cần đối chiếu sang người dùng thật thì phải đẩy kèm bảng người dùng — bảng này hiện chưa nằm trong file dữ liệu.
